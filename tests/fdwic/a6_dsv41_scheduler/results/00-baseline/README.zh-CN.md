**两端都已通过独立 SWA 的固定输入和参考输出校验。PR 主指标是 L0 首末计算核的时间。A5 迁移起点复测为 269.698 µs，当前分支为 269.286 µs。A6 为 370.307 µs，比当前 A5 多 101.021 µs（37.51%）。**

## 下界为何更高

当前 A5 的 L0 窗口为 **269.286 µs**，A6 为 **370.307 µs**，多 **101.021 µs**。用各自 L1 的核体时长求解，同步约束下界从 **133.030 增至 212.200 µs**，多 **79.170 µs**。两个差值分别来自 L0 和 L1，不能把两者相减当作调度开销。

**下界保留了实测的核体耗时。** 求解时可以省掉任务下发与领取的时间，但一个执行了 29 µs 的核仍占用对应的 C 或 V 约 29 µs。后继要等前驱最后一个实例结束。下界也保留 MIX 配对和同步启动，受可用 C/V 数量约束。[原 PR 计算模型](../../../dsv41_scheduler/BOUND.md)

在本用例中，有一条无法绕开的计算依赖链。以下为回放任务号，括号里的源码任务号用于查计划。

```text
t0 → t1 → t4 → t8 → t9 → t10 → t14 → t17 → t20 → t21 → t27
                          Q-B    Attention   O 量化   O-A    O-B    mHC 输出
                                  (源 t22)          (源 t28)
```

沿这条链，每个任务取耗时较长一侧的**单实例均值**再相加，A5 为 110.337 µs，A6 为 170.368 µs。即使有无限个核，一个任务也至少要等最慢实例结束，十轮的最慢实例均值至少等于对应侧的实例均值。按原模型每实例向下量化 0.1 µs，再扣除均值的显示舍入，A6 仅这条链就至少需要 **169.26 µs**。它已经比 A5 完整求解值高 **36.23 µs**。因此，单独增加 V 核也无法在保持这些核时长的条件下追平 A5。170.368 是对照用的小计，不能代替 212.200。[任务与分片](../../../dsv41_scheduler/workloads/pypto_lib_latest/swa/tasks.tsv) · [逐核 L1 数据](swa-l1-kernel-times.csv)

### 从单个 block 的均值算到 212.2 µs

用原 PR 模型固定依赖图和同步规则，先将同一任务、同一核类型的每个 block 设为该侧十轮 L1 均值，向下量化到 0.1 µs。下表前五项是本地 CPU 求得并验证可行排程的模型对照。最后一项采用 A6 逐轮以原始 block 时长求出的十轮均值。

| 模型输入 | 最短排程（µs） | 相对上行（µs） |
| -------- | -------------: | -------------: |
| A5 计划、32C／64V，各任务使用 A5 均值 | 110.2 | — |
| 换 A6 计划和 54C，暂留 64V、沿用 A5 均值 | 110.2 | 0.0 |
| 仅 Attention gather 和 O-A 两项换成 A6 均值 | 133.2 | +23.0 |
| 其余任务也换成 A6 均值 | 170.6 | +37.4 |
| V 容量从 64 改回实际的 54 | 190.8 | +20.2 |
| A6 每轮使用各 block 的实际时长 | **212.2** | **+21.4** |

**23.0 µs** 来自这条链上两个改过分片的任务。t14 Attention 的最长侧为 C，18.3 → 29.4 µs。t20 O-A 的最长侧为 V，16.8 → 28.7 µs。**37.4 µs** 来自其余任务均值的变化，其中 t10 Q-B 贡献 7.7 µs，t21 O-B 贡献 8.2 µs。以上是指定替换顺序下的模型差值，包含每项在两端观测到的全部核体差异。

**20.2 µs** 恰好是关键链上两次额外分批。t17 有 64 个 V block，每个按 11.0 µs 计，54 个 V 要运行两批，任务从 11.0 变成 22.0 µs。t27 同理，从 9.2 变成 18.4 µs。两个任务前后相依，分别增加的 11.0 和 9.2 µs 都落在最短排程上。

**21.4 µs** 是把均值替换回每轮真实 block 时长后出现的差额。后继要等最慢 block，MIX 要满足配对，多批的排程也受各 block 相对时长影响。例如 t21 在 A6 上平均 25.809 µs，十轮中最长一个达到 38.406 µs。仅凭各侧均值、最大值和逐轮最优解，无法把 21.4 µs 精确分摊到每一个任务。

比较两端正式下界时，A5 自己也有 **22.830 µs** 的实际时长与均值模型差额（133.030 − 110.2）。因此跨代增量是 **23.0 + 37.4 + 20.2 + (21.4 − 22.830) = 79.170 µs**。其中 +20.2 来自 L1 均值模型，下文的 +18.7 来自 L3 run5，使用了不同的核体时长。[L1 逐核输入](swa-l1-kernel-times.csv) · [求解器](../../../dsv41_scheduler/production/sync_bound.py)

## 哪些 kernel 变慢，哪些有实现上的解释

下表为 L1 十个正式轮次、每个执行实例的平均核体耗时，单位 µs。两端均以设备 `kernel_end_cycles − kernel_start_cycles` 计算。两端均按任务和 C/V 类型分组。19 种「计算任务 × 核类型」的均值均上升，幅度从约 1.20 倍到 1.82 倍。MIX 按实际核类型分开计数。[全部 19 项、实例数和最大值](swa-l1-kernel-times.csv)

| 回放任务（源码） | 核类型 | 每轮实例 A5 → A6 | A5 均值 | A6 均值 | A6/A5 |
| ---------------- | ------ | ---------------: | ------: | ------: | ----: |
| t14 Attention gather（t22） | C | 24 → 48 | 18.354 | 29.443 | 1.60 |
| 同上 | V | 48 → 48 | 12.884 | 23.440 | 1.82 |
| t20 输出投影 O-A（t28） | C | 32 → 32 | 11.737 | 20.962 | 1.79 |
| 同上 | V | 64 → 32 | 16.826 | 28.740 | 1.71 |
| t10 Q-B 投影（t18） | C | 32 → 32 | 13.127 | 20.894 | 1.59 |
| t17 输出量化（t25） | V | 64 → 64 | 6.885 | 11.007 | 1.60 |
| t21 输出投影 O-B（t29） | C | 32 → 32 | 17.656 | 25.809 | 1.46 |
| t27 mHC 输出（t35） | V | 64 → 64 | 6.978 | 9.257 | 1.33 |

**Attention 增加了实际工作。** A5 用一个 1C2V block 处理 64 个 head，两个 V 分担 KV gather。A6 将同一组 head 拆给两个 1C1V block，每个 block 只算 32 个 head，但各自的 V 都要 gather 完整的 64 条 KV。C 实例翻倍，单个 V 的 gather 也从 32 条变成 64 条。把这一任务的 C/V 核体时长逐实例求和，每轮从 **1,058.9 增至 2,538.4 核·µs**，约占全用例新增累计核时的 **49%**。这是并行区间之和。仅凭它不能判定每个 C 实例变慢多少来自配对等待、多少来自访存。[Attention 核](../../../dsv41_scheduler/kernels/pypto_lib_latest/vendor/external/sparse_gather_vf.cpp) · [计划转换](../../prepare_plan.py)

**O-A 把两个 V 的并行工作交给了一个 V。** A5 每个 block 的两个 V 各处理 128 列，A6 的一个 V 先后处理两半，C 侧也改为按 128 列生产并与 V 交接。单个 V 从 16.826 增至 28.740 µs，但 V 实例减半，每轮 V 的累计时间反而从 **1,076.9 降至 919.7 核·µs**。下一任务仍须等待较长的单 V 完成，仅看实例总数会低估这项延迟。[O-A 的生产、消费与列循环](../../../dsv41_scheduler/kernels/pypto_lib_latest/vendor/external/o_proj_a.cpp)

**其余 14 个计算任务的分片没改，累计核时仍从 2,878.5 增至 4,274.4 核·µs（+48.5%）。** O-B 是最干净的对照。它始终是 32 个纯 C block，在两端都能同时容纳，不涉及 C/V 交接。仍能看到每实例 **17.656 → 25.809 µs**。本地用同一份源码、同一 PTO-ISA pin 和编译器分别编译两种目标，O-B 反汇编中的 MXFP8 矩阵指令静态位置均为 **64** 个，Q-A 均为 **8** 个，Q-B 的 C 侧均为 **134** 个。静态数量无法给出指令执行次数或每条指令的等待周期。[O-B 分片](../../../dsv41_scheduler/kernels/pypto_lib_latest/vendor/external/o_proj_b.cpp) · [投影核的搬运、矩阵指令和等待](../../../dsv41_scheduler/kernels/pypto_lib_latest/vendor/external/mxfp8_projection.hpp)

核体计时覆盖调用内的搬运、矩阵／向量计算和同步等待。O-B 按 K 分块，在 GM→L1、L1→L0 和矩阵流水之间交接。要区分这些原因，优先用固定输入、相同 tile 的 O-B，比较两端单 block 与原 32 block，并对齐矩阵流水活跃周期、搬运等待和运行时核心频率。单 block 已慢可优先查单核流水；增至 32 block 才明显拉开，应优先查共享带宽或并发资源争用。当前材料还无法在这些原因之间定案。[核体计时边界](../../../../../src/a5/runtime/host_build_graph/aicore/resident_scheduler_impl.h)

## 54 个 V 的影响有多大

以 **A6 L3 run5** 做单变量对照。保持其 570 个实测区间长度、1C1V 分片、任务依赖和 54 个 C 完全相同，仅改变模型可用的 V 数量。每任务独立最短时间沿依赖链相加给出下界，同时用原 PR 求解器构造出相同时长的可行全图排程。MIX 全组同起的排程能达到该下界，无需从 CSV 猜测 block 配对。时长均按 100 ns 向下取整。此实验使用 L3 单轮，用来量化容量的影响，正式表中的 212.200 µs 来自 A6 L1 十轮。

| 模型中的 V 数 | t17 输出量化最短时间 | t27 mHC 输出最短时间 | 全图最短时间 |
| ------------: | -------------------: | -------------------: | -----------: |
| 54（A6 实际容量） | 22.3 µs | 18.3 µs | 234.9 µs |
| 64（仅改变模型容量） | 11.6 µs | 10.3 µs | 216.2 µs |
| 差值 | **10.7 µs** | **8.0 µs** | **18.7 µs** |

这两个任务各有 64 个 V block。在 54 个 V 上，至少 10 个要等第一批释放资源。在 run5 的 t27，前 54 个 block 全部结束于 **625.187 µs**，后 10 个从 **660.889 µs** 才开始，中间 **35.702 µs 全卡没有核体执行**。容量能解释为什么需要第二批；第一批已全退后还要等 35.702 µs，需要调度发布、领取或就绪事件才能定位。最后的 10 个核体只各用了约 9–10 µs。[代表轮空隙统计](#代表轮的全卡计算空隙)

**t17 和 t27 提供了一个能排除前驱依赖的观测窗口。** 两项各有 64 个普通 V block，计划均未设置同步启动。按 worker 逐条核对，A5 的每项任务各用了 64 个不同的 V，各执行一次；A6 的每项任务各用了 54 个 V，其中 10 个各执行两次。t17 两批的边界是 433.624 → 449.284 µs，t27 是 625.187 → 660.889 µs。两处合计 51.362 µs，占代表轮全卡空隙增量的 41.9%。第二批与第一批属于同一逻辑任务，图上的前驱在第一批执行时已经满足。对确实执行过两次的 10 个 V，逐核计算“第一次返回 → 第二次开始”，中位数分别为 **37.997 µs** 和 **41.117 µs**。

**合并前代码中，普通 block 返回后需要重新取得执行资格。** A6 实测版本 `9161810` 在核函数返回处记结束时间，再处理本次执行的完成记录。如果普通任务还有 block 待完成，会给当前 worker 留下继续处理同一任务的提示。主循环处理就绪槽；走同任务续领分支时，还须确认本地待下发任务仍匹配、执行槽可用，并用 GM 原子加一领取下一个 block。领到后才进入下一次核调用。该分支可以复用已满足的前驱。核体区间能定位两次调用间的时间；定位到具体调度分支还需要每个实例的完成处理、领号和准入时间戳，无法把这段耗时继续分到某次原子操作或某个调度分支。[核返回与完成处理](https://github.com/mihudaner/simpler/blob/91618108c/src/a5/runtime/host_build_graph/aicore/resident_scheduler_impl.h#L720) · [普通任务续领提示](https://github.com/mihudaner/simpler/blob/91618108c/src/a5/runtime/host_build_graph/runtime/scheduler/scheduler_completion.h#L260) · [续领条件与 GM 领号](https://github.com/mihudaner/simpler/blob/91618108c/src/a5/runtime/host_build_graph/runtime/scheduler/scheduler_execution_tokens.h#L175)

**t14 前的空隙另有同步启动约束。** 它依赖 Q-B 投影和 KV 发布两条分支。末个前驱核体结束到首个 Attention 核体开始，A5 为 28.651 µs（最后结束的是 KV 发布），A6 为 46.043 µs（最后结束的是 Q-B），相差 17.392 µs。这里覆盖前驱核返回后的逻辑完成、依赖就绪与 MIX 同步启动。合并前的计划把参与组数从 24 改为 48，仅凭两个端点无法确定新增时间有多少花在等各组就绪。
